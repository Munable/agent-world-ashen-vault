## 每类证据能说明什么

| 证据 | 已覆盖 | 不证明 |
| --- | --- | --- |
| 规则测试 | 具体输入、资源、版本和待决分支的代码行为。 | 完整 SRD 正确性、所有普通游玩路径。 |
| 三职业 × 三路线脚本 | 当前固定策略下可达性及部分状态不变量。 | 真人／模型胜率、游戏平衡、全部三级能力在正常主链可用。 |
| HTTP / MCP | 鉴权、schema、调用与恢复路径。 | 接收方 Agent 持续运行、理解消息或真实业务完成。 |
| 最终浏览器脚本 | 首屏三职业选项、Fighter 1→3 主链、原有恢复与表现检查。 | Rogue / Wizard 的完整浏览器主链或三职业全部技能体验。 |
| party 测试 | 独立身份共享状态、回合授权、奖励／休息边界。 | 完整多人探索、通话轮次、公裁或掉线后所有协作情况。 |
| 旧状态兼容测试 | v1 registry / G1 存档载入 v2 合同，保留角色和当前进度。 | 多次升级、长期积累及所有备份恢复场景。 |

三级特性测试通过人工设置 XP、构造战斗等夹具覆盖处理器；主链结束后才升级三级。这是有效单元证据，但不能改写成正常流程已经使用新能力，见 [G2_RULES](G2_RULES.md)。

## 对 Runtime 的反馈

共享私有状态授权推动 `authorization_state` 进入 Runtime；领域规则仍在世界包。此实验支持可移植状态与交互的部分合同，不代表底层逻辑已全部定义或长期运行已经成立。

后续只针对明确 Runtime 假设补最小实验，不把完整多人战役、更多法术或美术变成默认验收门槛。普通开发优先本地或可控机器；不为本次文档整理重跑既有计费 CI。
