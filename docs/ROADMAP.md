# 灰烬地城实施计划 v0.3

日期：2026-09-25。当前候选版本 0.3.0a1。

## 已完成基线

### M1
保留固定近战规则夹具，继续作为回合、移动、机会攻击、服务器 RNG、幂等和 HTTP/MCP 的回归基线。

### G1
六区域单人 Fighter 1→2 主循环已闭合：探索、通行分支、战斗、奖励、回营、休息、升级和占位表现。历史证据保留在 G1_VALIDATION。

### G2 当前候选
已经进入可验收状态，但仍是“有限规则预览”：

1. Fighter / Rogue / Wizard 三个固定构筑都能从 1 级成长到 3 级。
2. 3 级固定方向为 Champion / Thief / Evoker。
3. Rogue 的 Sneak Attack、Vex、Cunning Action、Steady Aim、Fast Hands 有实际规则路径。
4. Wizard 有有限法术准备、组件、法术位、Arcane Recovery、Shield 反应继续点和 Blur 专注。
5. 世界版本提升到 v2，并提供旧 G1 Fighter 存档迁移。
6. party.* 提供 1–3 独立身份的共享状态合作预览，验证成员授权、真人回合所有权、NPC 世界控制、奖励账本和休息共识。
7. 前端仍以占位资源为主；G2 最后一批规则改动后尚未重新跑完整真实浏览器整链，因此这仍是下一次本地验收的优先项。

## G2 继续收口

在扩内容前，优先完成：

- 最终候选的真实浏览器 Fighter / Rogue / Wizard 冒烟路径；
- Shield / 专注 / Fast Hands 的可见前端反馈复核；
- 完整多人探索/任务，而不是只停留在共享战斗预览；
- 死亡、战后救助、休息中断和断线等待的更完整边界；
- 少量继续扩展的 Wizard 法术，每个法术必须先闭合准备、资源、组件、反应/专注和表现，再开放给客户端。

## G3

扩展原创序章到约 8–12 区域，形成更清楚的 1→3 内容节奏、多路线资源压力、隐藏信息和多个终局。合作模式与单人模式共享任务事实，但保留成员私有信息与独立身份边界。

## G4

回归灯溪镇和灰烬地城，整理最小世界模板、开发者文档、表现资源绑定说明，并用少量强模型 canary 做真实 Agent 端到端验证。

## 持续约束

- 不把 Runtime 变成 D&D 专用内核。
- 不用 LLM 猜未实现规则。
- 不把每个用户的独立单机状态伪装成多人世界。
- 不因为测试方便给 NPC 越过真人反应/决策点。
- 常规开发优先本地或可控机器测试；GitHub Actions 只做必要的最终/发布级复核，避免高频 push 触发计费 CI。
