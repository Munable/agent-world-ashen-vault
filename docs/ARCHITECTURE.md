# 世界包架构和身份边界

本文首先描述已实现的 M1。完整游戏的目标边界见 [GAME_DESIGN.md](GAME_DESIGN.md)。世界二次开发是正式扩展方式；M1 没有修改内核是历史事实，不是后续禁止改进通用基础设施的约束。

## 依赖与分层

固定依赖 `agent-world` 0.13.1 / `422fc56fd63d383fb4dd262981810d88e5db0c73`。

- `rules.py`：有限机械规则基础函数，不读网络、不读数据库。
- `engine.py`：遭遇、回合预算、路径、反应窗口与裁决。复制输入状态后验证和执行，不在拒绝时留下局部变化。
- `world.py`：仅用 WorldDefinition、FunctionSpec、StateRule、FunctionContext、ViewSpec、StreamSpec 接入已有内核。
- `server.py`：组合已有 HTTP/MCP 传输和只读页面，不另写鉴权协议。
- `web/`：只读取已公布的场景与事件，不请求随机数、不裁决命中、不控制角色。

HP、AC、伤害、先攻、反应窗口完全属于世界包。通用内核未新增 RPG 字段或专用方法。没有导入灯溪镇代码，没有复制其地图、任务或 NPC，未引入新的 provider 依赖。

## 一次操作与一次随机结算

世界写入使用 `ctx.random_int`。随机取值在已提交操作回执中留痕；重复 operation_id 和相同参数返回原回执，不能重新掷骰。相同 ID 改参数失败。状态与事件由内核事务提交。

客户端先获取 turn_id，并将其作为普通动作的前置条件。操作幂等解决重复提交；turn_id 解决同一角色过期指令误入后续回合。这两者用途不同。

机会攻击窗口含窗口 ID、反应者、移动者、尚未执行路径。它属于服务器世界状态，不依赖一个进程内协程。反应完成后再继续移动；此前已返回的移动回执依然表示当时受理并暂停，不会被篡改成一个不同结果。用户应重新读取场景/公开事件查看最终位置。

## 用户身份

身份令牌由用户持有，客户端只是获准的执行者。M1 使用本地操作员配置工具发放，不新增网站账号系统。两个身份分别主动加入两个席位；不能通过请求参数指定其他人的 role_id 来占用席位。

**跨客户端可携带不等于跨世界无限通用。** 当前内核身份令牌绑定 universe；灯溪镇的令牌不能直接当作灰烬地城的令牌。跨世界稳定角色与各世界独立挂接数据仍是产品方向；目前共享角色档案或跨实例身份映射尚未完成，需要单独合同，M1 不伪造统一登录，也不把当前限制当作最终设计。

配置文件是私密文件，不提交 Git、不打印到日志，输出路径以独占创建方式避免覆盖已有钥匙。Windows 上文件权限继承宿主 ACL，不能把 POSIX mode=0600 描述为跨平台加密保险箱。初始化失败可能留下空文件或未使用角色；本地配置不是事务型公开注册服务。

## 公开前端和测试证据

公开投影显示这场实验的全部战斗数值，但不输出身份令牌和 owners 映射。页面只调用 public 路由，credentials=omit，不接收钥匙、不保存浏览器状态。观战不表示任何 LLM 正在持续运行。

`tests/test_mcp.py` 使用真正的 MCP 客户端与另一个 HTTP 客户端；这是传输/服务器验证，不是两个自主模型。固定骰点只在单元/HTTP 测试里通过测试替身控制；服务没有调骰 endpoint、公开种子或胜率调节入口。

## 保留限制

一个数据库只是一场双席位遭遇，没有战役列表、角色更换、战后重置或时间推进。新试验使用新的数据库路径，不自动删除旧场景。普通读取与观察没有动作副作用；持续对话和其他探索功能属于下一阶段。

冻结开发者 SDK 仍需后续职业/法术和完整地城通过，不能仅凭本次近战切片宣称底座已覆盖一切世界。

## 面向完整游戏的责任调整（尚未实现）

战役和持久角色不再等同于一场两席位遭遇；多场遭遇、成长、任务/奖励与 NPC 策略由世界二次开发完成。角色、遭遇实体和登录身份必须分清。

快照/流同步、事件去重、受权限约束的资源引用与基础播放工具优先复用现有接口；世界适配器负责将本世界事件映射成动作、效果和界面变化。数据容器已经存在不等于播放器已完成。

本世界遇到真实通用缺口可以改进底座，但 HP、先攻、职业、休息与任务奖励语义不进入核心。完整设计与实施顺序分别以 GAME_DESIGN 和 ROADMAP 为准，不在这里再维护一份并行玩法规格。


## G1 单人冒险实施补充（0.2.0a1）

G1使用独立WorldDefinition/universe `ashen-vault-ember`，不把M1两席位数据强行迁移成玩家存档。每个认证role_id挂接自己的campaign状态。世界层新增campaign_content（作者内容/构筑）、campaign（纯规则推进/脚本NPC）、campaign_world（现有SDK适配）和独立前端。

所有领奖来源、经验/金币/物品、成长和事件在世界事务中提交。revision阻止过期意图，operation_id解决同一请求重试，持久rewards记录阻止不同请求重复领奖。这三者并非重复的网络补丁。

世界脚本NPC只在世界代码里操作自己管理的enemy实体，并通过与玩家相同的战斗引擎结算。它不签发用户令牌、不冒充另一个role_id、不代理用户反应；每次自动推进最多12步，到需要真实用户决定处停止。

前端采用既有认证ViewSpec timeline与按角色投递的PresentationCue/EventSpec。快照和流锚点由同一次观察取得；私密战役不发布到M1的公共combat流。数据帧与语义结果一起提交，玩家/NPC来源明确。表现中的最终HP来自已提交事件，动画不再次修改服务器。

资源声明复用ViewSpec resources的asset URI，`asset://ashen-vault-ember/campaign-assets.json`绑定到本服务`/campaign-assets.json`。绑定表仅是已知几何形状、颜色和有界时长，不执行下载的脚本。两套占位资源通过真实浏览器轨迹验收；这不等于任意3D骨骼无需适配。

未探索的完整房间数据和非当前遭遇实体不进入玩家投影，其他角色无法借用视图游标或读取其私有事件。相邻出口ID仍是当前可用动作的一部分；本版本并不对已阅读开源内容的玩家隐藏作者地图设计。

世界内容的静态几何与返回给客户端/适配器的投影分离复制，防止调用者修改投影时污染权威规则常量。客户端不存储令牌；退出或权限撤销会清理页面数据。浏览器外的剪贴板/客户端日志仍由用户选择的可信宿主管理。

这是一条世界二次开发的实际路径，没有为了G1新增RPG专用内核字段、模型供应商适配、凭据保险箱、通用效果DSL或微服务。未来真正通用的缺口仍允许补到底座，不把“内核没变”当成绝对目标。
