# 灰烬地城的实验定位

范围调整：2026-09-26。替代原“扩展到完整游戏”的默认目标；不改变已发布代码或删除历史测试。原详细游戏提案保留在 Git 历史，不继续作为 Runtime 必须完成的产品合同。

## 目的

本世界用于验证 Agent World 的结构化接入、规则执行、持久状态、操作重试、待决继续点、共享状态授权和获准观察。已有游戏代码保留为复杂回归消费者。

Runtime 是世界运行时。身份由用户持有，Agent 在外部运行；服务端执行 schema、授权及开发者规则，不理解自然语言以产生裁决。统一身份目标与当前实现的差异由 Runtime 文档维护，本世界不另建登录哲学。

## 分工

| 层 | 当前职责 |
| --- | --- |
| Runtime | 函数、鉴权、事务、回执、状态与获准观察、可选定时事项。 |
| 世界包 | SRD 子集、角色状态、地图、任务、奖励、战斗继续点、脚本 NPC 与成员资格。 |
| 客户端／外部 Agent | 用户授权的结构化操作、推理与私人上下文、显示及本地连接管理。 |

脚本 NPC 是有界规则代码，不是服务器里的 Agent；不能替玩家回应。世界二次开发是正常路径，发现通用缺陷可以修 Runtime；“内核一行不改”不是验收目标。

## 保留与停止扩张的范围

保留 M1、G1、G2 已有规则／传输／恢复测试；精确范围见 [G2_RULES](G2_RULES.md)，不在此复制职业和法术清单。

不再把 8–12 区完整序章、更多职业法术、完整多人战役、美术和完整游戏 UX 当作 Runtime 验收门槛。独立游戏产品可另立需求，但不能自动转为本项目必须完成的研究任务。

新增世界内容只有在能对应明确 Runtime 假设、且现有夹具不能覆盖时才进入本轮计划。测试必须区分结构化脚本、真实传输、浏览器、外部模型和长期运行，不互相替代。

第三方／群众公裁继续作为 Runtime 交互逻辑的待设计方向，不在本游戏规则中预选方案，也不因为当前没有自动语义判断而排除。统一待办由 Runtime 的 [OPEN_DESIGN](https://github.com/Munable/agent-world/blob/main/docs/OPEN_DESIGN.md)维护。
